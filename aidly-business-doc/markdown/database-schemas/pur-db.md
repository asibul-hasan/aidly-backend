# PUR DB Script

<!-- Consolidated from the previous aidly-business-doc/backend, frontend, memory, and planning files. -->

PUR and SAL share the current migration script because they are commercially coupled through AR/AP and inventory/finance postings. PUR-owned sections define suppliers, purchase orders, GRN/invoice/return/payment, and AP ledger support.

### 2026-08-14 — contract & posting audit (no schema change)

The same audit found the PUR DTO layer had invented column names the database does
not use. `pur_order_dtl` / `pur_invoice_dtl` / `pur_receipt_dtl` / `pur_return_dtl` all
store `product_no` and `qty` (`order_qty` on the order), while the DTOs exposed
`item_no`, `item_code`, `item_name` and `quantity`. The frontend matched the database;
the wire contract did not, so **every line saved with a null product and zero quantity**.
Renamed to the real column names across PUR_1101/1102/1103/1105 — no schema change.
